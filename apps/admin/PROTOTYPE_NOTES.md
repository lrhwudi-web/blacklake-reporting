# ERP 主从后台设计结论

## 要回答的问题

在“左侧工单列表 + 右侧所选工单详情”的前提下，哪种信息层级最适合班组长日常报工管理？

最终选择 `工序台账`：左侧使用紧凑台账行；右侧把工序表放到最强位置，适合高频扫视进度。

## 原型边界

- 点击登录框中的“使用演示数据查看界面”可直接体验，数据只存在当前页面内存。
- 正式页面复用同域钉钉登录会话，并由反向代理鉴权后读取 `/v1/admin/assignments`；不向用户展示管理密钥输入框。
- 真实待核对操作仍调用现有 resolve 接口；演示模式不会写入服务器或黑湖。
- 页面不再包含方案参数或原型切换器。

## 当前结论

2026-08-25 选定第 2 个 `工序台账` 方案。原因：其他方案装饰和信息层级过多；最终界面应更克制、更紧凑，让班组长先看到工单、进度和工序。

已删除 `标准主从`、`核对优先` 及底部方案切换器，并将 `工序台账` 提升为 `/admin` 默认正式布局。

## 系统导航壳

- 一级功能固定在左侧：报工管理、人员、统计分析。
- 顶部显示当前会话最近打开的功能标签；报工管理固定不可关闭，其余标签可关闭。
- 切换功能不会丢失报工管理内已选工单和展开状态。
- 交互模式参考 Vue Vben Admin / Soybean Admin 的侧栏与多标签后台结构，但继续使用项目现有原生 JavaScript，不引入框架迁移。
